# W2 Features: detect, describe, match (L02, 105pp)
- VO pipeline p11-12: (1) visual correspondences (2) motion estimation (W4-5). Odometry: odos route + metron measure p6. Wheel encoders slip -> VO.
- Challenges p18-20: geometric (scale, rotation, perspective), appearance (light/shadow, season/weather, exposure/WB, blur/noise), ambiguity (repeated patterns, visual aliasing, low texture).
- Pipeline p21: detection (find good features), description ("fingerprint"), matching (use descriptors). ORB = FAST + BRIEF; SIFT = detector+descriptor p22. Table p23 classical vs learned: detection Harris/FAST/DoG(SIFT)/SURF/AKAZE vs SuperPoint/DISK/R2D2; description SIFT/SURF/BRIEF/ORB/BRISK/AKAZE vs SuperPoint/DISK/D2-Net/R2D2; matching NN/brute force/ratio/cross-check/ANN vs SuperGlue/LightGlue/LoFTR.
- Applications p24 (stitching, SfM, stereo, tracking, registration, AR, recognition, place recognition/loop closure, calibration).
- Good feature p36: distinctive, repeatable, well localised.
- Moravec 1980 p44-46: shift window in 8 directions, SSD s(u,v,δ)=Σ(I(u+δu+i,v+δv+j)-I(u+i,v+j))²; score C=min over shifts. Problems: high score on edges not at 0/90/45°, inefficient.
- Harris 1988 p47-50: derivatives Ju,Jv; structure tensor A = w * [[Ju², JuJv],[JuJv, Jv²]] (w = window/Gaussian weighting). Eigenvalues: both large=corner; one large one small=edge; both small=flat. Eigenvectors: directions of fastest/slowest change.
- Descriptors p54-58: naive raw patch SSD Σ(a-b)², SAD Σ|a-b| -> not invariant to rotation/scale/illumination.
- SIFT 1999/2004 p60-66: invariance to scale, rotation, moderate perspective, illumination, noise. Scale space: blur at increasing σ; DoG D(u,v,σ)=L(u,v,kσ)-L(u,v,σ); extrema vs 26 neighbours (8 same scale + 9 above + 9 below) in space AND scale; orientation via histogram of gradient orientations weighted by magnitude -> dominant orientation; clean-up removes edge-like, low-contrast, badly-localised; descriptor 4x4 subregions each orientation histogram (8 bins standard -> 128-D), concatenated 16 histograms.
- BRIEF 2010 p69-72: random pixel pair comparisons in patch, each 1 bit (slide: I(p)<I(q) ->... slide table shows I(p)>I(q)=1); e.g. 256 bits = 32 bytes; Hamming distance = XOR+popcount; very fast; NOT rotation/scale invariant; needs detector.
- FAST 2006 p76-78: circle of 16 pixels (Bresenham r=3); corner if N contiguous pixels all brighter than p+t or all darker than p-t (typically N>=12); high-speed test pixels 1,9,5,13: for corner at least 3 of the 4 must be brighter/darker; ML decision tree learns test order; no gradients/float/convolution.
- ORB 2011 p83-85: oFAST (scale pyramid like SIFT, Harris measure to reject line points, orientation = vector keypoint->intensity centroid) + rBRIEF (rotate test pattern by orientation).
- Matching p87-90: brute force, Euclidean (float descriptors) or Hamming (binary). Lowe ratio test ||A-B1||/||A-B2|| < θ (best/second best). Cross-check (mutual NN): discard (A1,B1) if some A2 is closer to B1. Always refine; geometric verification (RANSAC) later.
- Learned matching p91-95: joint assignment problem; table p92 traditional (independent, ratio/cross-check rules, fixed thresholds, same compute each pair) vs learned (joint reasoning, learns mutual consistency, predicts correspondences AND unmatched, adaptive compute e.g. LightGlue). SuperGlue p93: features exchange info within image (context) and across images; output accepted matches + rejected unmatched features.
- Summary table p97: Harris detector, rotation (partly), medium; FAST detector none, very fast; SIFT det+desc scale+rotation slow, patent expired; SURF det+desc scale+rot faster (integral images); ORB det+desc rotation, scale(limited), real-time; BRIEF descriptor not rot invariant very fast binary.
- Learned p98: LIFT, DISK (policy gradient), SuperPoint (self-supervised, joint points+desc), SuperGlue, LightGlue. Trend p99-100: sparse learned vs detector-free/dense (LoFTR etc.) help low-texture.
- Practical choice p101-103: hardware, latency, conditions. Baseline: ORB + Hamming brute force + ratio test/cross-check; SIFT for large scale/viewpoint change, weak texture, fewer-but-reliable matches; ANN when large; RANSAC when false matches remain.
- Prac Week_02: KITTI intro notebook + LightGlue demo (SuperPoint + LightGlue on KITTI; saved outputs).

## Papers
SuperGlue (Sarlin et al. CVPR 2020; P02a 18pp, slides P02s): "middle-end" (data association) between front-end feature extraction and back-end pose/MAP. Inputs: two sets of M,N local features: keypoint coords + confidence, descriptors. Keypoint encoder (MLP on position) + descriptor -> attentional GNN, alternating self-attention (intra-image) and cross-attention (inter-image), 9 layers -> score matrix -> dustbin row/col (unmatched) -> Sinkhorn (differentiable soft Hungarian, optimal transport, 100 iters) -> partial assignment (each keypoint ≤1 match). GT from pose+depth; loss = neg log-likelihood of GT assignment incl. unmatched. 12M params, 69 ms (15 FPS) GTX1080 indoor pair (p5).
- Table 2 (p6) indoor ScanNet, SuperPoint features: AUC@5/10/20 %, Precision P, Matching score MS: NN+mutual 9.43/21.53/36.40, P 50.4, MS 18.8; NN+OANet 11.76/26.90/43.85, 74.0, 25.7; SuperGlue 16.16/33.81/51.84, 84.4, 31.5.
- Table 4 ablation (p7) AUC@20 / precision / MS: NN+mutual 36.40/50.4/18.8; No GNN 38.56/66.0/17.2; No cross-attn 42.57/74.0/25.3; No positional enc 47.12/75.8/26.6; Smaller (3 layers) 46.93/79.9/30.0; Full (9 layers) 51.84/84.4/31.5. => GNN explains most of gain; cross-attention & positional encoding critical; depth improves precision.
- Limitations (for discussion): depends on detector (no keypoints -> nothing to match), quadratic attention cost/memory in #keypoints, GPU needed, sparse.
LightGlue (Lindenberger, Sarlin, Pollefeys ICCV 2023; P02b): revisits SuperGlue design; more efficient (memory+compute), more accurate, easier to train (few GPU-days vs SuperGlue). Adaptive: depth (early exit when confident, per-layer confidence classifier) and width (prune points deemed unmatchable early). Still needs external sparse detector/descriptor (SuperPoint, DISK) -> sparse matcher.
- Table 2 MegaDepth1500 relative pose, RANSAC AUC 5/10/20, LO-RANSAC AUC, time ms (SuperPoint): NN+mutual 31.7/46.8/60.1, 51.0/54.1/73.6, 5.7ms; SuperGlue 49.7/67.1/80.6, 65.8/78.7/87.5, 70.0ms; LightGlue 49.9/67.0/80.1, 66.7/79.3/87.9, 44.2ms; adaptive 49.4/67.2/80.1, 66.3/79.0/87.9, 31.4ms. Dense LoFTR 52.8/69.2/81.2, 181ms.
- Table 5 adaptive (easy/medium/hard/avg): stopping layer 4.7/5.5/6.9/5.7 (of 9); unmatchable points pruned % 19.8/23.4/27.9/23.7; speedup 1.86/1.33/1.16/1.45. Adaptive cuts run time ~33%. Full model 35% faster than SuperGlue (Fig 7). Fig 1: ~8x faster than LoFTR with accuracy close to it.
- Tutorial Q answers hints: easy pairs = large overlap, little appearance change; sparse method; dense/detector-free (LoFTR) preferable for low texture.
