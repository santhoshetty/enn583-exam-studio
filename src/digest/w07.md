- Direct vs indirect p18-25: indirect (feature-based) minimise geometric reprojection error from matched features. Direct: minimise photometric error R*,t* = argmin Σ_i (I_{k-1}(x_{k-1}^i) − I_k(π(K(R p_i + t))))²; can jointly optimise p_i (dense BA objective) p23; DTAM dense tracking & mapping p24. Table p25: direct = photometric error, pixel intensities, implicit correspondence through projection, semi-dense/dense maps, high subpixel precision, sensitive to illumination & camera modelling (needs photometric calibration, brightness constancy), requires good initial guess (small convergence basin). Feature-based = reprojection error, feature locations, descriptor matching, sparse landmark maps, larger convergence basin, tolerant of photometric changes, better for large motions & relocalisation.
- 2x2 p36: indirect-sparse (PTAM, ORB-SLAM, libviso); indirect-dense (dense optical flow + reprojection); direct-sparse (DSO); direct-dense (DTAM); LSD-SLAM semi-dense direct p38.
- VIO p26-35: IMU = gyroscope (angular velocity) + accelerometer (linear acceleration); MEMS p28. Why IMU: mono scale ambiguity (accelerometer gives metric scale; gravity), vision fails in low texture, under/over-exposure (low dynamic range), motion blur p29. Why not IMU alone p30: double integration of noisy acceleration -> large drift quickly; constant accel bias -> position error grows quadratically with time (½ b t²). Complementary table p31: camera exteroceptive, sensitive to blur/HDR/texture, drift bounded when observing same scene, precise slow motion, ~100 Hz, scale ambiguous (mono); IMU proprioceptive, insensitive to blur/HDR/texture, drift unbounded, less precise slow (low SNR), 1,000–10,000 Hz, prior to predict feature positions. Both dead-reckoning. Model p32: ã_B = R_BW(a_W − g) + b_A + n_A; ω̃_B = ω_B + b_G + n_G; biases slowly varying random walk ḃ = σ_b w; change with temperature/pressure, differ each power-on, can be estimated p33. VIO objective p34-35: argmin over states X (pos, vel, orientation), landmarks L, biases b_A,b_G of Σ ||f(x_{k-1},u) − x_k||²_Λ (IMU residuals, preintegration) + Σ Σ ||π(x_k,L_i) − z_k^i||²_Σ (reprojection/BA term).
- Evaluation p39-44: ATE: average Euclidean distance estimated vs GT positions; captures accumulated drift, metres, intuitive; limits: needs spatial & temporal alignment, single RMSE hides where/when errors happened, sensitive to outliers, doesn't separate translation drift from rotation-induced error, misleading for mono if scale fitted over whole trajectory. Alignment p41: similarity (R,T,s) = argmin Σ||Ĉ_k − sRC_k − T||², then RMSE = sqrt(Σ||Ĉ_k − sRC_k − T||²/n); captures global error not local. Single early rotation error -> huge ATE p42 -> use RPE. RPE p43: E_i = (T̂_{i-1}⁻¹ T̂_i)⁻¹ (T_{i-1}⁻¹ T_i) difference of relative motions; RPE_trans = sqrt(1/(N−1) Σ ||trans(E_i)||²) (also rotation). ## ORB-SLAM3 (Campos et al., T-RO 2021, P07)
- First system doing visual, visual-inertial and multi-map SLAM with mono, stereo, RGB-D, pinhole & fisheye. Novelty 1: feature-based tightly-integrated VI SLAM fully relying on MAP estimation even in IMU initialisation; 2–10x more accurate than previous. Novelty 2: multi-map (Atlas) with new place recognition (improved recall): when lost, start new map, merged seamlessly when revisiting. Reuses all previous info (co-visible keyframes far apart in time / previous sessions -> high-parallax BA). Stereo-inertial: 3.5 cm avg EuRoC drone; 9 mm TUM-VI room.
- Components (Fig 1, Sec III): Atlas (active map + non-active maps; one DBoW2 keyframe database for relocalisation, loop closing, map merging); Tracking thread (pose of current frame vs active map in real time minimising reprojection error of matched map features; decides keyframes; VI: velocity & IMU biases; if lost, relocalise in all Atlas maps, else after a while store map as non-active and start new one); Local mapping thread (add keyframes & points, cull redundant ones, local (visual or VI) BA in window of keyframes near current frame; IMU init & refinement via MAP); Loop & map merging thread (at keyframe rate detects common regions active map vs Atlas: same map -> loop correction; other map -> merge into one active map; after loop correction full BA in separate thread).
- Sec VI: short/mid-term association by projecting map points; long-term via DBoW2 bag of words (raw precision/recall 50–80%; with temporal+geometric checks 100% precision, 30–40% recall; temporal check delays ≥3 keyframes) -> ORB-SLAM3 new place recognition, local window of covisible keyframes for mid-term associations.
- Loop closing: welding window, fuse duplicate points, pose-graph optimisation (essential graph) to propagate correction, then global BA (VI: only if #keyframes below threshold).
- Relocalisation = tracking lost, find pose in existing maps (no prior pose); loop closure = revisit in active map -> correct drift; map merging = revisit area of a non-active map -> merge maps.
- Keyframes: reduce redundancy/compute, give parallax; cost = map coverage vs. efficiency; culling redundant keyframes.
- Optimisation roles: tracking (motion-only BA / pose optimisation), local BA (local window), pose graph / essential graph (loop correction propagate cheaply), full/global BA (after loop closing; refine all).
