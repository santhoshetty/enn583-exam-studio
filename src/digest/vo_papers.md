# VO Part I (Scaramuzza & Fraundorfer, IEEE RAM Dec 2011, P04) & Part II (Fraundorfer & Scaramuzza, RAM June 2012, P05)
Part I:
- p1: VO = egomotion from cameras only; term coined by Nister 2004; analogous to wheel odometry; needs illumination, static textured scene, overlap; not affected by wheel slip; relative position error 0.1–2%.
- p4 Reducing drift: errors accumulate frame to frame -> drift; windowed (sliding-window) BA over last m poses; Konolige 10 km: windowed BA reduces final position error by factor 2–5; fuse GPS/laser/IMU.
- p4-5 VO vs V-SLAM: SLAM goal = global consistent estimate of path, keeps map to detect loop closure (return to visited area) -> reduce drift in map and path; VO = incremental, local consistency only ("VO is only concerned with the local consistency of the trajectory, whereas SLAM with the global consistency"). V-SLAM: filtering vs keyframe (non-filtering) methods.
- p5 Formulation: T_{k,k-1} = [[R, t],[0,1]] ∈ R^{4x4} relative motion between k-1 and k; C_k pose w.r.t. frame 0; C_n = C_{n-1} T_n (concatenation); C_0 arbitrary. Main task: compute T_k from I_k,I_{k-1}, concatenate; optional windowed BA over last m poses. Fig 1. Appearance-based (global) vs feature-based (more accurate, cheaper).
- p7-8 motion estimation types: 2D-2D (both in 2D: E, 5-point Nister minimal), 3D-3D (both 3D: point registration, 3 non-collinear points), 3D-2D (f_{k-1} in 3D, f_k in 2D).
- p9 Relative scale: triangulate X_{k-1}, X_k from subsequent pairs; r = ||X_{k-1,i} − X_{k-1,j}|| / ||X_{k,i} − X_{k,j}||; mean or median over many pairs; requires features tracked over ≥3 frames; alternative trifocal constraint.
- Algorithm 1 (2D-2D): 1 capture I_k; 2 extract & match features I_{k-1},I_k; 3 compute E; 4 decompose E into R_k,t_k form T_k; 5 compute relative scale & rescale t_k; 6 C_k = C_{k-1} T_k; 7 repeat.
- p10 3D-2D more accurate than 3D-3D (minimises image reprojection error rather than 3D position error): argmin_T Σ ||p_k^i − p̂_{k-1}^i||²; PnP (resection); minimal P3P gives 4 solutions, disambiguated by extra points; P3P standard for robust estimation with outliers; DLT for n≥6. X_{k-1} from stereo or (mono) triangulation needing 3 views.
Part II:
- p6 Outlier removal "most delicate task in VO" (causes: noise, occlusion, blur, viewpoint/illumination changes). RANSAC standard; model = relative motion (R,t), data = candidate correspondences, inliers by point-to-epipolar-line distance (Sampson = first-order approx) or Oliensis directional error. N = log(1−p)/log(1−(1−ε)^s) (ε outlier fraction, s sample size); often ×10 in practice; non-deterministic. Algorithm: sample s, fit, distances, inlier set, keep max, FINAL: re-estimate model using all inliers.
- Minimal parameterisation: N exponential in s -> prefer minimal (5-point calibrated; 8-point fails for planar scenes...).
- p8 Is minimal better? For speed yes; with very noisy correspondences, a non-minimal set averages noise -> more accurate, more inliers.
- Error propagation: Σ_k = J diag(Σ_{k-1}, Σ_{k,k-1}) Jᵀ = J_C Σ_{k-1} J_Cᵀ + J_T Σ_{k,k-1} J_Tᵀ (first-order); 6-vector poses; "camera-pose uncertainty is always increasing when concatenating transformations" -> keep individual uncertainties small. Fig 8 ellipses.
- Camera pose optimisation: transformations T_{k,k-2},…,T_{k,k-n} or any T_ij used as extra constraints.
- p9 Pose graph: nodes = camera poses, edges = rigid-body transformations; cost Σ_{eij} ||C_i − T_{eij} C_j||²; rotation makes it nonlinear -> Levenberg–Marquardt.
- Loop constraints: edges between far-apart nodes; loop detection via visual similarity (global descriptors or bag of visual words: k-means vocabulary, histogram distance, inverted file), then geometric verification with epipolar constraint, compute rigid transform -> add loop edge.
- Windowed BA: optimises camera poses AND 3D landmarks over window of n frames; min Σ ||p_k^i − g(X_i, C_k)||² reprojection error; LM; needs init close to minimum (two-view VO); needs features tracked over >2 frames; window size governed by computation, O((qM + lN)³); can fix landmarks (e.g. accurate stereo) to reduce cost.
