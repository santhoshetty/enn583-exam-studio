# W5 Visual odometry: 2D-2D scale, 3D-2D PnP, 3D-3D, keyframes (L05, 98pp)
- Recap p4-8: F, E, RANSAC removes matches violating x'ᵀEx=0; 2D-2D gives R correct, t direction only.
- Scale ambiguity p12-14: t̂ unit direction; t = s·t̂ unknown s>0. Scaling translation and scene by same s leaves image observations unchanged: K(R sX + s t) = s K(RX+t) -> same pixel after dividing by depth.
- Recover scale with known 3D points (stereo/depth) p15-18: s* = argmin_s Σ ||x_i^obs − π(K(R p_i + s t))||² (reprojection error; nonlinear LS; scipy).
- Optimisation template p19: parameters (s) / prediction (projected pixel) / residual (reprojection error) / objective (sum of squares). Problem table p20 (exact->solve; noisy linear->QR/SVD; noisy nonlinear->GN/LM; outliers->robust loss/RANSAC).
- 3D-2D localisation p22-27: 1 point -> camera anywhere on ray (infinite); 2 points -> infinite but bounded (angle θ maintained); 3 points -> up to 4 solutions (P3P), 4th point disambiguates (OpenCV SOLVEPNP_AP3P, Ke & Roumeliotis CVPR17); ≥4 -> PnP, EPnP O(n) (Lepetit 2009).
- PnP objective p28-29: argmin_{R,t} Σ ||x_i − π(K(R p_i^{w} + t))||².
- Practical pipeline p30-34: P3P/AP3P inside RANSAC = minimal hypothesis generator + outlier filter + initial guess; EPnP fast many-point (vulnerable to outliers); iterative refinement (LM/GN) minimises reprojection error over inliers, needs initial guess, vulnerable to outliers. Generic pipeline p31: observations (many, outliers) -> minimal solver + RANSAC -> inliers (guaranteed* outlier-free) + initial guess -> refinement (iterative nonlinear LS) -> solution. Table p32: P3P/AP3P: 3 correspondences mathematically, OpenCV commonly uses 4; does NOT directly minimise reprojection error (exact algebraic; reprojection error scores hypotheses); outlier vulnerability high alone, robust inside RANSAC. EPnP >4, algebraic, high vulnerability. Iterative LM/GN: directly minimises reprojection error; high vulnerability with ordinary LS -> use RANSAC inliers + optional robust loss. OpenCV p33: solvePnP(flags P3P/AP3P/EPNP/ITERATIVE), solvePnPRansac, solvePnPRefineLM, solvePnPRefineVVS.
- Build-a-VO discussion p36: features+matching, stereo depth, F/E, RANSAC, P3P/PnP, decompose E, reprojection error, scale from stereo.
- 3D-3D p37-70 (Arun, Huang, Blostein 1987): x_t^i = R x_{t-1}^i + t; argmin Σ||x_t^i − (R x_{t-1}^i + t)||²; never exactly zero (noise). Steps: (1) centroids; (2) subtract centroids; (3) H = Σ x̄_{t-1}^i x̄_t^iᵀ (cross-covariance, outer products), USVᵀ = svd(H), R = V Uᵀ (degenerate/reflection cases det=-1); (4) t = x̄_t − R x̄_{t-1}. Camera motion = inverse of the point-alignment transform p69. Not very accurate p70: stereo/triangulated 3D points have large depth error (diamond-shaped uncertainty); better to minimise image-level quantities (reprojection error).
- Methods recap p72: 2D-2D, 3D-3D, 3D-2D estimate ^{C_{k}}T_{C_{k-1}}.
- Keyframes p75-80: frame-to-frame errors accumulate even if camera static (random-walk drift); estimate motion relative to last keyframe ^{K}T_{C_k}. New keyframe heuristics p78: motion threshold, feature tracking quality (too many lost), time-based; too few -> poor map, too many -> inefficient. Mono rule p80: keyframe when keyframe distance / average depth > threshold (10–20%); small baseline -> large depth uncertainty. Pure rotation: no baseline -> cannot triangulate.
